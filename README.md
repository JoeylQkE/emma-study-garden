# Emma 的学习花园

温柔的学习打卡网页，支持五项学习任务、月历、顶部成长小花、奖励转盘、可保存的兑换卡和独立测试模式。静态页面无需安装依赖；开通云端后，Emma 和 Joey 使用预先创建的账号登录。

## 直接测试

下载并用浏览器打开 `emma-test.html`，默认进入测试模式。这是单文件离线版。推荐 Chrome、Edge 或 Safari；允许浏览器存储才能在刷新后保留记录。

测试面板可以切换日期、一键打卡、模拟连续 3 / 7 / 14 天或考前全勤、指定是否获得机会和指定转盘奖品、无限增加测试机会、重置测试数据。批量操作从所选日期开始，只补未打卡日期，不重复判定。测试记录和日常记录使用不同存储键，互不影响。测试面板只存在于本地测试文件中；公开页面忽略 `?mode=test` 等参数。

修改源文件后，运行 `python3 tools/build-test.py` 更新单文件测试版。

## 本地运行

在本仓库运行：

```sh
python3 tools/build-public.py
python3 -m http.server 3000 --bind 0.0.0.0 --directory public
```

服务首页是公开版，没有测试入口。测试只能打开单独的 `emma-test.html`，该文件不会包含在公开发布目录。不要在未来任务中默认创建 Git worktree，直接使用现有隔离检出。

## 当前规则

- 五项任务：背单词、听力、阅读、作文、口语。背单词每天必选。
- 工作日：背单词＋其余四项任选至少两项即可签到。
- 周末：仅背单词即可签到，没有抽奖概率；单词＋两项以上可抽奖，并固定获得一次补签机会。
- 单词＋两项 / 三项 / 四项的抽奖机会概率分别是 35% / 55% / 80%。提交签到后当天任务和概率锁定，每天只判定一次，刷新不会重新抽取。
- 转盘中的外卖、唱歌、读故事、奶茶各有 25% 概率，消耗一次机会。
- 连续 3 / 7 / 14 天解锁外卖、巧克力、零食大礼包，每档只解锁一次。
- 漏签会中断连续天数。周末赚到的补签机会可补 2026-10-11 至 2026-11-09 期间已经过去的漏签日，恢复连续签到并重新检查奖励。一次机会补一天，不额外发放抽奖或补签机会。已解锁奖励保留。
- 2026 年 10 月 11 日至 11 月 9 日共 30 天全勤（包括补签），解锁“神秘惊喜”；11 月 10 日考试。
- 小花只在页面顶部右侧显示，按累计天数成长；漏签不会枯萎。每日鼓励话语在标题下方，每天从 100 条中随机选一条，当天刷新不变。
- 连续奖励、全勤奖励、转盘奖品都会生成可保存为 PNG 的兑换卡，写有“请找 Joey 兑换”。关闭后从“我的奖励收藏”搜索、重新打开。测试兑换卡明确标记为模拟奖励。
- 旧版 v2 打卡、机会和连续奖励会保留并迁移，不重新抽取概率。

测试面板默认折叠，点“测试实验室”展开。可以选模拟完成量，强制机会结果，模拟多天，以及一键建立断签场景：10 月 14 日漏签，10 月 17 日周六赚到一次补签机会，补上后从 3 天恢复为 7 天，解锁巧克力兑换卡。

未配置云端时，数据保存在当前浏览器；清除浏览器数据会丢失记录。配置云端后，Emma 与 Joey 使用各自的邮箱账号访问同一份记录，数据库控制写入权限。测试文件仍只使用独立本机记录。奖品由你们安排实际兑现。

## 公开发布

```sh
python3 tools/build-public.py
```

`public/` 只包含单文件公开页面和 `.nojekyll`，不包含测试工具或测试数据。`emma-public.html` 可独立打开，`emma-public.zip` 可直接上传静态网站托管平台。

手机端按今日打卡、月历、连续奖励、转盘、奖励收藏的顺序排列；按钮扩大，兑换卡适配小屏幕。已验证 320、360、390、430、768 像素宽度。

GitHub Pages 发布使用 `gh-pages` 分支的根目录。首次需要在仓库 Settings → Pages 中确认 Source 为 Deploy from a branch，选择 gh-pages 和 /(root)。公开页面不包含测试工具。云同步未配置时，手机和电脑记录独立；按下方指南开通后共享云端数据。

## 云端共享

阅读 [Supabase 开通指南](supabase/README.md)。新建项目、执行数据库脚本、创建并绑定 Emma 与 Joey 两个账号，然后填入 SUPABASE_URL 和 SUPABASE_PUBLISHABLE_KEY。

Emma 可写入学习、签到、抽奖、补签，Joey 查看同一份记录。页面每 10 秒同步，也支持手动更新。抽奖在数据库生成并保存，所有写入由账号角色检查；请求编号用于断网重试去重。导入只允许 Emma 操作，且云端必须为空，原本机数据保留。

前端和 SQL 脚本已通过本地集成验证，真实 Supabase 云项目尚未配置。复现测试（Docker 与 Playwright/Chromium 可用时）：

```sh
bash tools/test-cloud.sh
```

此脚本创建并清理专门的 PostgreSQL 测试容器、临时 HTTP 服务，使用虚拟账号模拟登录传输；数据库权限和数据写入实际执行于 PostgreSQL。它不会连接云端项目或处理真实账号密码。
